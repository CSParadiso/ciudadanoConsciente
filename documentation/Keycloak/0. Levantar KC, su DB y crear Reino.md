**LEVANTAR BASE DE DATOS Y KEYCLOAK EN CONTENEDORES**
Lo primero es lo primero: crear la base de datos desde el contenedor y levantar keycloak asociándolo a esa DB. En este caso se utiliza un archivo ".env" para ocultar las variables con datos sensibles:
```yaml
kc_db:
    image: postgres:16                     # Nombre de la imagen
    container_name: kc_db                  # Nombre del contenedor
    deploy:
      resources:
        limits:
          memory: 100M                     # Limitar a 100MB 
    restart: always
    environment:
      POSTGRES_PASSWORD: ${PASSWORD_DB_KC} # PASSWORD de la DB
      POSTGRES_USER: ${USERNAME_DB_KC}     # USERNAME de la DB
      POSTGRES_DB: ${KEYCLOAK_DB}          # NOMBRE de la DB
    ports:
      - 3701:5432                          # Mapear puertos externo:interno
    volumes:
      - kc_data:/var/lib/postgresql/data   # Mapear volumen para persisitir datos
      - ./init_KC.sql:/docker-entrypoint-initdb.d/init.sql  # Montar los scripts de inicialización

keycloak:
    image: quay.io/keycloak/keycloak:25.0 # Nombre de la imagen
    container_name: keycloak              # Nombre del contenedor
    deploy:
      resources:
        limits:
          memory: 1000M                   # Limitar la memoria a 1GB
    restart: always                       # Reiniciar siempre 
    ports:
      - 3703:8080                         # Mapear puertos externo:interno
    environment:
      - TZ=America/Argentina/Ushuaia      # Timezone para la JVM
      - KEYCLOAK_ADMIN=${KEYCLOAK_ADMIN}  # Usuario admin
      - KEYCLOAK_ADMIN_PASSWORD=${KEYCLOAK_ADMIN_PASSWORD} # Password admin
      # Cuestiones de Proxy para Nginx
	  - KC_HOSTNAME_STRICT=false
      - KC_HTTP_ENABLED=true # Migrado desde KC23 -- KC_PROXY=edge # permite HTTP (https://www.keycloak.org/docs/25.0.2/upgrading/#deprecated-proxy-option)
      - KC_PROXY_HEADERS=xforwarded
      - KC_PROXY_PROTOCOL_ENABLED=true
      - PROXY_ADDRESS_FORWARDING=true
      - KC_DB_URL=${KEYCLOAK_DB_URL}     # URL de la DB
      - KC_DB=postgres                   # TIPO de DB  
      - KC_DB_SCHEMA=${KEYCLOAK_DB_SCHEMA} # SCHEMA de la DB
      - KC_DB_USERNAME=${USERNAME_DB}    # USERNAME de la DB 
      - KC_DB_PASSWORD=${PASSWORD_DB}    # PASSWORD de la DB
      - KC_FEATURES=docker,admin-fine-grained-authz,organization
      - KC_HEALTH_ENABLED=true
      - KC_METRICS_ENABLED=true
    command: start --log="console,file" 
    volumes:
      - logs:/opt/keycloak/data/log/ # Mapear volumen para persistir logs

```
Script de inicialización que debe estar en el mismo directorio que el compose.yaml:
```sql
---------------- INICIO SCRIPT -----------------

\connect keycloak;

-- Establecer horario local en la DB
SET TIMEZONE TO 'America/Argentina/Ushuaia';

-- Crear esquema y asignar permisos
DO $$
BEGIN
    -- Crear esquema 'keycloak' si no existe
    IF NOT EXISTS (SELECT 1 FROM information_schema.schemata WHERE schema_name = 'keycloak') THEN
        CREATE SCHEMA keycloak;
    END IF;
    
    -- Asignar permisos al usuario
    GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA keycloak TO citizen_admin;
    GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA keycloak TO citizen_admin;
END $$;

-----------------------------------------------------------------------
```

---

Una vez creados los tres archivos (`.env`, `compose.yaml` y `kc.sql`), nos posicionamos en el directorio y levantamos el contenedor 
```bash
>>> ls -la 
# Output
.env
compose.yaml
kc.sql
>>> docker compose up -d
```

**CONSOLA DE ADMINISTRACIÓN DE KEYCLOAK**
1. Ingresamos en el navegador la URL de la consola (en este caso localhost) y el puerto externo (definido en el compose, 3703): http://localhost:3703.
2. Es necesario utilizar las credenciales que definimos en el archivo `.env` como `KEYCLOAK_ADMIN` y `KEYCLOAK_ADMIN_PASSWORD`.

**CREAR REINO**
Para crear un Reino debemos seleccionar en la pestaña de la izquierda arriba y seleccionar luego "Create Realm". 
![[CrearReinoEnKeycloak.png]]

Luego, indicamos el nombre del reino y decidir si habilitarlo o no con el toogle "Enabled". Finalemente, se crea con el botón "Create".
![[CrearNombreReinoEnKeycloak.png]]

**CONFIGURAR REINO**
En la pestaña de la izquierda abajo, seleccionamos "Realm settings" y en la pestaña "General" podríamos tooglear Organizations a ON para habilitar la funcionalidad Organizations (aún en modo PREVIEW) y seleccionamos "Save". 
![[PestanaGeneralReinoEnKeycloak.png]]

En la pestaña "Login" es importante que toogleemos a ON "User Registration" para permitirle a Keycloak registrar clientes y servirnos así a unos de sus propósitos principales que es la gestión, autenticación y autorización de usuarios. El resto de los campos y pestañas queda a consideración del administrador: roles y grupos por defecto, campos que se solicitan en el registro, sesiones, tokens, localizaciones, etc.
![[PestanaLoginReinoEnKeycloak.png]]

**CREAR GRUPOS**
Los roles que hayamos creado, se los podemos mapear a Grupos a los que luego añadiremos usuarios que heredarán esos Roles.
En la pestaña de la izquierda seleccionamos "Groups" y cuando nos aparezca el contenido del menú seleccionamos "Create group". ![[Pasted image 20240807143352.png]]
Elegimos un nombre para el grupo (vamos a tratar de mantener los grupos en minúsculas) y seleccionamos "Create".
![[Pasted image 20240807143646.png]]

A los grupos se les puede asignar subgrupos para mayor granularidad. Vamos a usar esta característica de Keycloak para mapear nuestros roles. Una vez seleccionado un grupo, en la pestaña "Child groups" seleccionamos "Create group" y repetimos el proceso anterior.

Tanto a los grupos como a los subgrupos podemos mapearles roles. Una ves seleccionado el grupo o subgrupo deseado, buscamos la pestaña "Role mapping" y le seleccionamos"Assign role". 
![[Pasted image 20240807144259.png]]

 Luego, tildamos el checkbox del rol desde la lista de roles y seleccionamos "Assign".  
 ![[Pasted image 20240807144508.png]] 
---


**AGREGAR USUARIOS A GRUPOS (y herederar los roles)**
Ahora que tenemos grupos que tiene mapeados roles, podemos unir usuarios a grupos y que estos hereden esos roles. Esto nos permite en nuestro cliente determinar el rol de un usuario a través del AccessToken y de esta manera permitirle o no el acceso a un recurso.

En la pestaña "Users", seleccionamos un usuario y luego dentro del perfil del usuario seleccionamos la pestaña "Groups" y el botón "Join Group".
![[Pasted image 20240807145432.png]]
Seleccionamos algún grupo o subgrupo al cual querramos agregar al usuario y seleccionamos "Join".
![[Pasted image 20240807145524.png]]
