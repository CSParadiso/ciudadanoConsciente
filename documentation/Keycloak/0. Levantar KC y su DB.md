**LEVANTAR BASE DE DATOS Y KEYCLOAK EN CONTENEDORES**
Lo primero es lo primero: crear la base de datos desde el contenedor y levantar keycloak asociándolo a esa DB. En este caso se utiliza un archivo ".env" para ocultar las variables con datos sensibles:
```yaml
kc_db:
    image: postgres:16                     # Nombre de la imagen
    container_name: kc_db                  # Nombre del contenedor
    deploy:
      resources:
        limits:
          memory: 100M                     # Limitar a 100MB 
    restart: always
    environment:
      POSTGRES_PASSWORD: ${PASSWORD_DB_KC} # PASSWORD de la DB
      POSTGRES_USER: ${USERNAME_DB_KC}     # USERNAME de la DB
      POSTGRES_DB: ${KEYCLOAK_DB}          # NOMBRE de la DB
    ports:
      - 3701:5432                          # Mapear puertos externo:interno
    volumes:
      - kc_data:/var/lib/postgresql/data   # Mapear volumen para persisitir datos
      - ./init_KC.sql:/docker-entrypoint-initdb.d/init.sql  # Montar los scripts de inicialización

keycloak:
    image: quay.io/keycloak/keycloak:25.0 # Nombre de la imagen
    container_name: keycloak              # Nombre del contenedor
    deploy:
      resources:
        limits:
          memory: 1000M                   # Limitar la memoria a 1GB
    restart: always                       # Reiniciar siempre 
    ports:
      - 3703:8080                         # Mapear puertos externo:interno
    environment:
      - TZ=America/Argentina/Ushuaia      # Timezone para la JVM
      - KEYCLOAK_ADMIN=${KEYCLOAK_ADMIN}  # Usuario admin
      - KEYCLOAK_ADMIN_PASSWORD=${KEYCLOAK_ADMIN_PASSWORD} # Password admin
      # Cuestiones de Proxy para Nginx
	  - KC_HOSTNAME_STRICT=false
      - KC_HTTP_ENABLED=true # Migrado desde KC23 -- KC_PROXY=edge # permite HTTP (https://www.keycloak.org/docs/25.0.2/upgrading/#deprecated-proxy-option)
      - KC_PROXY_HEADERS=xforwarded
      - KC_PROXY_PROTOCOL_ENABLED=true
      - PROXY_ADDRESS_FORWARDING=true
      - KC_DB_URL=${KEYCLOAK_DB_URL}     # URL de la DB
      - KC_DB=postgres                   # TIPO de DB  
      - KC_DB_SCHEMA=${KEYCLOAK_DB_SCHEMA} # SCHEMA de la DB
      - KC_DB_USERNAME=${USERNAME_DB}    # USERNAME de la DB 
      - KC_DB_PASSWORD=${PASSWORD_DB}    # PASSWORD de la DB
      - KC_FEATURES=docker,admin-fine-grained-authz,organization
      - KC_HEALTH_ENABLED=true
      - KC_METRICS_ENABLED=true
    command: start --log="console,file" 
    volumes:
      - logs:/opt/keycloak/data/log/ # Mapear volumen para persistir logs

```
Script de inicialización que debe estar en el mismo directorio que el compose.yaml:
```sql
---------------- INICIO SCRIPT -----------------

\connect keycloak;

-- Establecer horario local en la DB
SET TIMEZONE TO 'America/Argentina/Ushuaia';

-- Crear esquema y asignar permisos
DO $$
BEGIN
    -- Crear esquema 'keycloak' si no existe
    IF NOT EXISTS (SELECT 1 FROM information_schema.schemata WHERE schema_name = 'keycloak') THEN
        CREATE SCHEMA keycloak;
    END IF;
    
    -- Asignar permisos al usuario
    GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA keycloak TO citizen_admin;
    GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA keycloak TO citizen_admin;
END $$;

-----------------------------------------------------------------------
```

---

Una vez creados los tres archivos (`.env`, `compose.yaml` y `kc.sql`), nos posicionamos en el directorio y levantamos el contenedor 
```bash
>>> ls -la 
# Output
.env
compose.yaml
kc.sql
>>> docker compose up -d
```
